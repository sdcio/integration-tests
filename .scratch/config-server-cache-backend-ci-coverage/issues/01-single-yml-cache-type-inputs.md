# 01 — `single.yml`: `cache_type` + suite-selection inputs

**What to build:** Extend the reusable `single.yml` workflow with two new optional inputs so a caller can deploy `data-server` with the alternate cache backend and choose a reduced set of test suites to run:

- `cache_type` (default `local`): when set to `config-server`, the existing "Set the versions to test" step's `yq`-patch mechanism (the same one already patching in `DEVIATION_INTERVAL` and the trace-level flag) additionally patches `cache.type: config-server` and `cache.address: 127.0.0.1:56010` into the generated `data-server` ConfigMap. When left at `local`, the generated ConfigMap is unchanged from today's behavior.
- A suite-selection input controlling which of the hardcoded `00`–`03` steps actually run (so a caller can skip `02-crud`/`03-deviations`). The existing "Run Robot Tests 04+ - Additional suites (auto-discovered)" step's glob-based discovery is left as-is — it naturally only picks up whichever `04+` suite directories exist, so no change is needed there for suite *discovery*, only for which of the explicit `00`–`03` steps execute.

Default behavior (both inputs at their defaults) must be unchanged from today — `cicd.yml` and `matrix-cicd.yml` continue to work without modification until ticket 03 wires in the new job.

**Blocked by:** None — can start immediately.

**Review notes (code-review pass, `/code-review`):** Standards review flagged that nothing in the workflow enforced `CONTEXT.md`'s "Cache-backend suite" invariant — "never against the same deployment as `02-crud`/`03-deviations`, since `Cache.Type` is fixed at deploy time" — a misconfigured caller could pass `cache_type: config-server` together with `02-crud`/`03-deviations` in `suites_to_run`. Fixed with a new fail-fast "Validate cache_type / suites_to_run combination" step that errors before any cluster is deployed if that combination is requested. The review also flagged that the original `contains(inputs.suites_to_run, 'XX-yyy')` guards did unanchored substring matching (a future suite name that's a substring of another, e.g. a hypothetical `02-crud-v2`, could false-positive-match `02-crud`); all six guards now use comma-delimited matching (`contains(format(',{0},', inputs.suites_to_run), ',02-crud,')`) to make matching exact-token. Spec review found no missing/partial requirements, no scope creep, and no functional defects within ticket 01's scope.
